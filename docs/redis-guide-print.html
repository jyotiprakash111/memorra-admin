Memorra Redis Guide

Implementation, benefits, and setup
Memorra Admin Panel + API · Version 1.0 · May 2026

1. Overview

Redis is a fast in-memory data store used by the Memorra backend for rate limiting, caching, and optional sessions. It sits alongside PostgreSQL (Neon) — Postgres holds permanent data; Redis holds short-lived or high-frequency data.

The backend lives in memorra-adminpanel (Next.js). Mobile and admin clients call /api/v1/*.

2. Benefits for Memorra

BenefitWhy it matters
Faster responsesCache funeral music, homes, FAQs, CMS theme
Shared across serversVercel serverless instances share one Redis
Rate limitingProtect admin login and mobile APIs
Less database loadNeon for durable data; Redis for hot reads
Sessions / revocationLogout-everywhere, token blocklists
Future real-timePub/sub for live streams, notifications

Without Redis: in-memory fallback works in dev on one machine — not for production at scale.

4. Project structure

memorra-adminpanel/lib/redis/
├── client.ts       → Upstash (prod) or ioredis (local)
├── rate-limit.ts   → Distributed limits + fallback
├── cache.ts        → JSON cache with TTL
├── session.ts      → Optional sessions
└── index.ts

Provider priority

  1. UPSTASH_REDIS_REST_URL + token (Vercel)
  2. REDIS_URL=redis://localhost:6379 (Docker)
  3. Neither → in-memory fallback

5. Setup

5.1 Local (Docker)

cd memorra-adminpanel
npm run redis:up

Add to .env: REDIS_URL=redis://localhost:6379

Verify: GET http://localhost:3000/api/v1/health

5.2 Production (Upstash)

  1. Create database at console.upstash.com
  2. Set UPSTASH_REDIS_REST_URL and UPSTASH_REDIS_REST_TOKEN on Vercel

6. Code usage

Rate limiting

import { checkRateLimit } from "@/lib/redis"

const result = await checkRateLimit(`login:${ip}`, {
  maxRequests: 10,
  windowSeconds: 900,
})
if (!result.allowed) { /* return 429 */ }

Caching

import { cacheKey, cacheGet, cacheSet } from "@/lib/redis"

const key = cacheKey("catalog", "funeral-music")
const cached = await cacheGet(key)
if (cached) return cached
const data = await prisma.funeralMusic.findMany(...)
await cacheSet(key, data, 300)
